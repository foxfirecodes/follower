# Repository testing and examples

- This repository may be tested against other repositories. Keep their names, paths, package identifiers, source excerpts, enum values, configurations, and trace output out of this repository unless explicitly approved for publication.
- Use small synthetic examples in documentation, fixtures, and tests. Put repository-specific behavior behind project or query configuration rather than hardcoding it in the engine.
- Keep real target project configurations and generated reports in the target repository or another private location. Checked-in configurations here must be samples or self-contained fixtures.
- Before finishing work that involved another repository, scan source, documentation, fixtures, tests, generated files, and staged changes for details from that repository.
